# A 股 / ETF 量化研究台原型设计

日期：2026-08-08

状态：历史设计基线；首版已实施，当前实现以仓库根目录 `README.md` 和代码为准

默认研究标的：512480.SH（国联安中证全指半导体产品与设备 ETF）

## 当前实现说明（2026-08-28）

本文保留 2026-08-08 的首版目标和验收口径，不再作为逐项描述当前 UI 的操作手册。当前实现与原设计的主要差异如下：

- 前端已重构为“风险收益课”和“技术状态课”，强调初学者解释、学习评分和区间联动。
- 当前主界面展示收盘价折线及 MA20/MA60、MACD、RSI 14、布林带和 ATR 等指标，不展示 K 线与成交量，也不提供独立指标开关。
- 双均线回测、缓存刷新 API 和对应前端组件仍在代码中，但当前 `App.tsx` 没有挂载回测与手动刷新入口。
- 资产资料增加统一路由 `GET /api/instruments/{code}/profile`；原 ETF 和股票专用路由继续保留。
- 数据缓存现按提供器隔离，演示数据使用独立版本化数据库；Tushare Token 可来自环境变量或 Token 文件。

当前安装、配置、测试命令和 API 清单见仓库根目录 `README.md`。

## 1. 背景与目标

本项目是供个人研究学习使用的本地 Web 量化分析系统。第一版聚焦单个 A 股或场内 ETF 的综合研究，以 512480.SH 作为默认标的，并允许用户搜索和切换其他代码。

原型必须做到：

- 通过 AkShare 与 Tushare 获取真实、可追溯的市场数据；
- 用统一数据模型隔离第三方接口差异；
- 提供行情、技术指标、风险收益、按资产类型切换的基本面/ETF 特征和基础策略回测；
- 通过现代、克制的 Web 页面解释指标含义、数据区间与计算口径；
- 为以后增加高级因子、策略、组合分析和更多数据源保留清晰扩展点。

系统只用于历史数据研究，不预测未来价格，不给出买卖建议，也不连接券商或执行交易。

## 2. 范围

### 2.1 首版包含

- 代码搜索与标的切换，默认加载 512480.SH；
- 日线 OHLCV 行情与本地增量缓存；
- K 线、成交量、均线、MACD、RSI 和布林带；
- 收益、波动、夏普、索提诺、最大回撤等风险收益指标；
- ETF 概况、跟踪指数、规模/份额、流动性和主要持仓；
- 普通 A 股的公司概况、估值与最近可得财务摘要；
- 双均线策略及与买入持有的回测对比；
- 数据来源、更新时间、缓存状态和质量告警；
- 公式与参数说明；
- 演示数据模式，但必须明确标识为演示数据。

### 2.2 首版不包含

- 用户、权限、云端同步和多人协作；
- 实时盘口、Tick 级行情和盘中交易信号；
- 自动下单或券商连接；
- 新闻情绪、机器学习预测和自动参数优化；
- 多股票组合优化和实盘绩效归因；
- 生产级高可用部署。

## 3. 技术架构

采用本地分层架构：

```text
React + TypeScript + ECharts
             ↓ REST / JSON
           FastAPI
             ↓
  analytics / backtest services
             ↓
 unified provider interface + validation
        ↙                    ↘
    AkShare                Tushare
             ↓
       SQLite cache
```

### 3.1 前端

- React、TypeScript、Vite；
- ECharts 展示 K 线、成交量、技术指标、净值和回撤；
- 前端只负责交互、状态和展示，核心金融计算均由后端完成；
- 使用响应式布局，桌面宽屏优先，窄屏按纵向卡片排列。

### 3.2 后端

- FastAPI 提供 REST API、请求校验和错误响应；
- Pandas 与 NumPy 负责时间序列处理和指标计算；
- 按 `data_providers`、`analytics`、`backtest`、`api` 划分模块；
- Pydantic 模型定义前后端稳定的数据契约。

### 3.3 本地存储

- SQLite 保存标准化日线数据、标的信息、ETF 补充数据与同步元数据；
- 以证券代码、交易日期和数据类型建立唯一约束；
- 查询优先读取缓存，只请求缺失日期并执行幂等 upsert；
- 演示数据与真实数据分表或使用明确的 `is_demo` 标志隔离。

## 4. 数据获取与质量

### 4.1 数据源策略

- AkShare 为默认主源，适合免 Token 的本地研究；
- Tushare 为备用和交叉校验源，Token 从 `TUSHARE_TOKEN` 环境变量读取；
- 未配置 Tushare Token 时系统正常运行，但明确显示备用源未启用；
- Tushare 接口因积分或单独权限不可用时，系统不得将权限错误描述为数据为空。

### 4.2 统一接口

每个数据提供器实现同一组能力，首版至少包括：

- 获取证券基础信息；
- 获取指定日期范围的日线 OHLCV；
- 获取 ETF 基本资料；
- 获取 ETF 规模/份额；
- 获取 ETF 主要持仓；
- 获取普通 A 股公司概况、估值和财务指标；
- 获取基准或跟踪指数行情（数据源支持时）。

适配器把第三方字段统一为内部模型，包括：证券代码、交易日、开盘、最高、最低、收盘、成交量、成交额、来源和抓取时间。价格和成交量单位在适配层完成归一化。

### 4.3 降级规则

1. 查询本地缓存并确定缺失区间；
2. 请求 AkShare；
3. 若网络失败、返回空集、关键字段缺失、日期乱序或 OHLC 关系异常，则请求 Tushare；
4. 已配置 Tushare 时，在首次完整同步和用户手动刷新时额外读取最近 20 个交易日做交叉校验；两个来源均成功时，对交易日、收盘价和成交量记录差异；
5. 两个来源均失败时返回已有缓存；无缓存则返回结构化错误；
6. 响应始终携带实际来源、缓存命中、更新时间和质量告警。

质量检查至少覆盖：重复日期、非递增日期、缺失 OHLC、负成交量、`high < low`、收盘价超出高低区间以及异常长的交易日缺口。

## 5. 页面与视觉设计

视觉方向采用“研究手记”：暖白背景、深墨色正文、砖红强调色、轻边框和充足留白。整体更像专业投研报告，而不是高饱和交易终端。

### 5.1 页面结构

1. 顶部导航：产品标识、代码搜索、数据源状态、最后更新时间和刷新按钮；
2. 标的概览：名称、代码、最新可得收盘价、对应交易日涨跌幅、成交额、区间收益和风险声明；
3. 核心行情：K 线与成交量联动，支持 3 月、6 月、1 年、3 年和全部区间；
4. 量化诊断：趋势、动量、波动和回撤四类评分及解释；
5. 资产信息：ETF 显示基金概况、跟踪指数、规模、份额、流动性、持仓和集中度；普通 A 股显示公司概况、估值与财务摘要；
6. 策略实验室：参数输入、策略净值、基准净值、回撤、交易点和绩效表。

### 5.2 图表交互

- K 线和成交量共用时间轴、十字光标和缩放范围；
- MA5/10/20/60、MACD、RSI、布林带可按需显示；
- 区间切换必须重新计算区间相关指标；
- 回测图同时展示策略净值与买入持有净值，并单独展示回撤；
- 图表 tooltip 显示日期、数值、单位和必要的指标解释。

### 5.3 状态设计

- 首次加载使用骨架屏；
- 空数据、权限不足、降级数据和演示数据采用不同提示；
- 单个资产信息模块失败时不阻断行情和回测；
- 用户输入错误时保留当前页面数据，并在搜索区域附近说明修正方式。

## 6. 量化分析方法

### 6.1 收益与风险

- 简单日收益率：`r_t = close_t / close_(t-1) - 1`；
- 累计收益：日收益复利累计；
- 年化收益：按 252 个交易日将样本期收益年化；
- 年化波动：日收益标准差乘以 `sqrt(252)`；
- 夏普比率：`(年化收益 - 可配置无风险利率) / 年化波动`；
- 下行波动与索提诺比率；
- 最大回撤与最长回撤持续时间；
- 具有基准数据时计算 Beta、相关性和区间超额收益。

年化收益在样本不足一年时仍可展示，但必须标记为“短样本年化”，避免把外推结果误解为长期表现。

### 6.2 技术分析

- SMA：5、10、20、60 日；
- MACD：默认 12、26、9；
- RSI：默认 14 日；
- 布林带：默认 20 日、2 倍标准差；
- 20/60 日滚动年化波动；
- 价格在近期高低区间中的位置。

趋势、动量和波动评分由公开的规则组合而成。页面必须能查看每个分项规则与当前触发条件，不使用不可解释的预测模型。

### 6.3 ETF 特征

- 基金管理人、成立日期、跟踪指数等基础信息；
- 最新可得规模与份额及其变化；
- 成交额、换手或其他可得流动性代理指标；
- 前十大持仓及集中度；
- 同时获得价格与净值时计算折溢价；
- 同时获得 ETF 与基准指数行情时计算跟踪偏离。

某项数据不可获取时，该项显示“暂不可用”及原因，不使用估算值填充。

### 6.4 普通 A 股基本面

- 公司名称、所属行业、上市日期和主营业务摘要；
- 最新可得市盈率、市净率、总市值和流通市值；
- 最近四个报告期的营业收入、归母净利润和同比变化；
- 最新可得 ROE、毛利率、净利率和资产负债率；
- 财务数据必须标注报告期，估值指标必须标注交易日；
- 缺少或不适用的指标显示“暂不可用”，不跨报告期拼接成未经说明的数值。

## 7. 回测设计

首版仅实现双均线策略：

- 快线由下向上穿越慢线产生目标多头信号；
- 快线由上向下穿越慢线产生目标空仓信号；
- 使用下一交易日开盘价执行，避免使用当日收盘后才完整形成的信号；
- 若下一交易日开盘价缺失，则跳过该次执行并记录告警；
- 仅允许全仓持有或空仓，不做卖空和杠杆；
- 手续费与滑点为可配置的单边成本；
- 默认快线 20 日、慢线 60 日，且快线必须小于慢线；
- 指标热身区间不计入绩效；
- 输出策略与买入持有的净值、年化收益、波动、夏普、最大回撤、交易次数、胜率和交易明细。

首版不自动寻优。代码结构预留训练/验证区间参数，便于后续加入滚动验证和稳健性分析。

## 8. API 契约

首版 API 按用途拆分：

- `GET /api/instruments/search?q=`：搜索证券；
- `GET /api/instruments/{code}`：基础信息；
- `GET /api/market/{code}/daily?start=&end=`：标准化日线；
- `GET /api/analysis/{code}?start=&end=`：技术与风险分析；
- `GET /api/etf/{code}`：ETF 专属资料；
- `GET /api/equity/{code}`：普通 A 股公司概况、估值与财务摘要；
- `POST /api/backtests/ma-cross`：运行双均线回测；
- `POST /api/data/{code}/refresh`：刷新缓存；
- `GET /api/health`：服务和数据源可用性。

所有业务响应包含 `data` 和 `meta`。`meta` 至少包含来源、查询区间、抓取时间、缓存状态、演示数据标志和质量告警。错误响应包含稳定错误码、用户可读信息和可执行的修复建议。

## 9. 安全与配置

- `.env` 不提交 Git，仓库只提供 `.env.example`；
- 后端日志不得输出 Token；
- 前端无法读取 Tushare Token；
- 搜索代码、日期、均线周期、费率和滑点均在后端验证；
- CORS 默认只允许本地前端地址；
- 页面固定展示“仅供个人研究学习，不构成投资建议”。

## 10. 测试与验收

### 10.1 自动化测试

- 指标单元测试：使用手工可验证的小样本检查收益、波动、最大回撤和技术指标；
- 回测单元测试：检查信号滞后一日、成本、热身期、交易记录和空数据；
- 适配器契约测试：使用固定响应样本检查字段和单位归一化，不依赖实时网络；
- API 测试：覆盖正常查询、非法代码、数据源降级、缓存回退和无权限；
- 前端测试：覆盖指标渲染、区间切换、错误状态和回测提交；
- 端到端检查：启动前后端并完成 512480 的行情、分析和回测流程。

### 10.2 验收标准

- 新环境按 README 可完成依赖安装与一键启动；
- 只启用 AkShare 时核心行情、分析和回测可用；
- 配置 Tushare Token 后可显示备用源状态，并在主源异常时降级；
- 512480 页面可展示真实日线、指标、风险统计和双均线回测；
- 切换到普通 A 股代码时，页面自动隐藏 ETF 模块并展示公司基本面模块；
- 每个结果可追溯到数据源、时间区间、参数和计算口径；
- 外部数据不可用时使用明确错误或显式演示模式，不把模拟结果冒充真实数据；
- 桌面和窄屏页面均无关键内容遮挡或横向溢出。

## 11. 后续演进

在原型边界稳定后，可按独立模块逐步增加：

1. 更多规则策略、滚动验证与参数稳健性分析；
2. 指数成分、行业暴露、估值与盈利质量聚合；
3. 多标的对比与组合风险分析；
4. 因子研究、事件研究和研究笔记持久化；
5. 定时数据同步与可部署架构；
6. 在有明确评估基准后引入可解释的高级模型。

新增能力继续通过统一数据模型、独立分析服务和版本化 API 接入，避免把数据抓取、计算与页面展示耦合在一起。
